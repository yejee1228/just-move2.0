### H-01 홈 〔D-19〕
기획자 요청으로 홈에는 **할 일 하나만** 둔다: 알림 버튼과 움직이기 카드. 카드는 수정 전 움직이기 카드와 같은 구성(한마디 → 버튼 → 이어서 하기 → 오늘 상태 줄)이고, 배경을 밝게 바꾸고 [지금 움직이기] 자리에 자세 버튼 2×2를 넣었다. 나머지는 각 탭에서 본다. 배치·모양은 design-spec §7 H-01.

| 순서 | 요소 | 동작 | 출처 |
|---|---|---|---|
| 1 | 로고 "JUST MOVE" + "생각은 그만, 일단 움직여요." | 고정 | 기존 |
| 2 | **알림 버튼** | 다음 알림 시각("14시 알림" / "내일 9시 알림") 또는 "알림 꺼짐" 표시, 누르면 P-02 | 〔R03-17〕 해석 |
| 3 | **오늘의 한마디** | 시간대별 문구, 움직이기 카드 맨 위 + 안내 "지금 자세를 고르면 1분 영상이 바로 시작돼요" | 〔R04-01〕 |
| 4 | **자세 버튼 2×2** | [누워서] [앉아서] [서서] [걸으며] — 자세 색 바탕 + 아이콘 + 이름. 누르면 그 자세로 M-01 바둑판이 열림 (고른 자세는 기억, "지난번" 표시) | 〔R04-07〕 〔D-19, D-20〕 |
| 5 | [멈춘 운동 이어서 하기] | 멈춘 운동이 있을 때만, M-03 | 〔D-09〕 |
| 6 | **오늘 상태 한 줄** | "오늘 n분 움직였어요 · 물방울 n/5" / 처음이면 "오늘의 첫 1분을 시작해 볼까요? · 물방울 0/5" | 해석 |

## 5. 추천 로직 (바둑판 순서, 2026-10-26 기획자 최신안) 〔D-23〕
서비스 기획서 §7-2. 기획서 원본의 추천 우선순위 6규칙을 대체한다. 요약:
- 후보: 고른 자세의 사용 중인 영상 전부 ('전체'면 모든 자세), 난이도로 거르지 않음
- 기본 순서: '첫 동작' 지정 영상 → 콘텐츠 순서
- 맞춤 점수 = 하트 +5 + 끝까지 본 횟수 × 1 + 고른 횟수 × 0.5 − 중간에 넘긴 횟수 × 1. 점수가 높은 순, 같으면 기본 순서
- 이어 볼 목록 = 체크박스로 고른 영상(고른 순서) 또는 누른 영상 + 추천 영상, 최대 10개. [계속 운동하기]는 방금 본 영상을 뺀 추천 영상
- 코드: `lib/recommend.ts` (`rankVideos`, `videoScore`, `playlistFrom`), 테스트 `lib/rules.test.ts`

| 기록 시점 | 쌓는 값 |
|---|---|
| 바둑판(또는 예약)에서 영상을 누를 때 | 그 영상의 고른 횟수 +1 |
| 운동 1회가 끝날 때(M-04 도착, 또는 멈춘 운동이 날짜가 바뀌어 확정될 때) | 조금이라도 본 영상마다 재생 +1, 그 영상 길이의 80% 이상이면 끝까지 본 횟수 +1, 아니면 중간에 넘긴 횟수 +1, 마지막 시청 시각 |

## 10. 개발 방식: 로컬 우선, 베타에서 서버 연결 〔D-15〕

| 기능 | 로컬 단계 | 베타 단계 |
|---|---|---|
| 운동 흐름·영상·시간 측정·추천 | 기기 안에서 동작 (영상은 `public/videos/`) | 영상을 저장소/CDN으로 |
| 기록·농장·환영·통계 | 기기 저장소 | 서버 저장 |
| 운영 콘텐츠 | `data/content/*.json` | 스프레드시트 자동 반영 |
| 관리자 지표 | 개발용 화면(한 기기) | 대시보드 |
| 운동 영상·광고 올리기 | 브라우저 IndexedDB (올린 브라우저에서만 보임) | 저장소/CDN + 관리자 로그인 |
| 하트·조회수·광고 결과 | 기기별 집계 | 서버에서 전체 사용자 합계 |
| 로그인 | 모의 로그인 | 카카오·구글 + 기록 이전 |
| 알림 | 앱이 열려 있을 때 정각 안내 | 웹 푸시 |

화면은 데이터 접근 계층(`data/repository.ts`)만 사용하므로, 베타 때 저장 방식만 서버로 바꾸면 된다. 서버·로그인·푸시 계정은 베타 단계에서 만든다.
